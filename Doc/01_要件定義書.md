## 1. システム概要 / System Overview

Porociaは、企業向けの**統合社内ポータル (Integrated Internal Portal)** である。
チャット・お知らせ・カレンダー・社員名簿・ナレッジベースを一つのプラットフォームに統合し、社内コミュニケーションの効率化を目的とする。

| 項目 | 内容 |
|------|------|
| **システム名** | Porocia |
| **システム種別** | 社内コミュニケーション・情報管理ツール (B2B / Internal Tool) |
| **対象ユーザー** | 企業の全従業員およびシステム管理者 |
| **現バージョン** | 0.1.0 (Beta) |
| **稼働環境** | クラウド (Firebase / Vercel) |

---

## 2. 背景と目的 / Background & Purpose

### 2.1 背景

現在、多くの企業では社内コミュニケーションに複数のツールを並行利用している（チャット、カレンダー、ドキュメント管理、人事管理など）。その結果、以下の課題が生じている。

- **情報の分散**: 従業員が複数ツール間を行き来する必要があり、生産性が低下する
- **権限管理の不統一**: ツールごとに権限設定が異なり、一元管理が困難
- **ライセンスコストの増大**: 複数のSaaSサービスに重複してコストが発生する

### 2.2 目的

本システムは上記課題を解決するため、社内コミュニケーションに必要な機能を一つのプラットフォームに統合することを目的とする。

## 3. ビジネス目標 / Business Objectives

| # | 目標 | 説明 |
|---|------|------|
| 1 | 社内コミュニケーションの一元化 | 複数ツールを本システムに集約し、情報断絶を防ぐ |
| 2 | 情報伝達の迅速化 | 全従業員への重要通知をリアルタイムで届ける |
| 3 | 社内ナレッジの蓄積・活用 | 業務ドキュメント・手順書を一元管理し、新入社員のオンボーディングを効率化する |
| 4 | スケジュール共有の促進 | 個人・グループ・全社のカレンダーを一元管理し、日程調整の手間を削減する |
| 5 | 従業員体験の向上 | シンプルで使いやすいUIを提供し、システム利用率を高める |

| お知らせ (Announcements) | 投稿・固定・コメント・リアクション | ✅ 完了 |
| カレンダー (Calendar) | 個人/グループ/全社イベント管理、複数表示モード | ✅ 完了 |
| 社員名簿 (People Directory) | メンバー一覧、検索、プロフィール閲覧、DM起動 | ✅ 完了 |
| ナレッジベース (Knowledge Base) | Markdownによる記事作成・閲覧・検索・アクセス制御 | ✅ 完了 |
| プロフィール (Profile) | 個人情報の閲覧・編集、アバター画像アップロード | ✅ 完了 |
| 管理者ダッシュボード (Admin Dashboard) | メンバー・グループ・お知らせ管理、統計表示 | ✅ 完了（一部） |

### 4.2 対象外範囲 (Out of Scope)

以下は本バージョンのスコープ外とし、将来フェーズで対応予定とする。

- 外部サービス連携（Google Calendar、Slack、Microsoft Teamsなど）
- ネイティブモバイルアプリ（iOS / Android）
- プッシュ通知・メールリマインダー
- 高度なレポート・分析機能
- オフラインモード

## 6. 権限モデル / Authorization Model

### 6.1 ユーザーロール

| ロール | コード | 権限 |
|--------|--------|------|
| 一般従業員 | `member` | チャット利用、個人カレンダー管理、お知らせ閲覧、ナレッジベース閲覧（許可範囲）、プロフィール編集 |
| 管理者 | `admin` | Member の全権限 ＋ メンバー・グループ・お知らせ・全社イベント・Admin専用資料の管理 |

### 6.2 コンテンツ公開範囲

| 範囲 | コード | 閲覧可能なユーザー |
|------|--------|-----------------|
| 全社 | `company` / `public` | ログイン済みの全従業員 |
| グループ | `group` / `private` | 該当グループのメンバー ＋ Admin |
| 個人 | `personal` | 作成者のみ |
| Admin専用 | `admin` | `admin` ロールを持つユーザーのみ |

## 7. 非機能要件 / Non-Functional Requirements

| カテゴリ | 要件 | 目標値 |
|---------|------|--------|
| パフォーマンス | 画面応答時間 | 通常操作で 200ms 以内 |
| パフォーマンス | 初回ページ表示 (FCP) | 4G回線で 2秒以内 |
| 可用性 | システム稼働率 | 業務時間内 99.5% 以上 |
| セキュリティ | 認証方式 | HTTP-only Session Cookie + Firestore Security Rules |
| セキュリティ | 機密データ | パスワード非保持；Firebase Auth で認証情報を管理 |
| スケーラビリティ | 同時接続ユーザー数 | SMEフェーズで 500ユーザー以上 |
| ユーザビリティ | レスポンシブ対応 | Desktop (≥992px)・Tablet (768〜991px) で正常表示 |
| 法令遵守 | 個人情報保護 | 個人情報保護法に準拠 |

## 8. 制約条件 / Constraints

| 制約 | 内容 |
|------|------|
| 技術的制約 | Next.js App Router / TypeScript strict mode を採用。Server Components を優先する |
| インフラ制約 | Firebase (Firestore / Auth) および Cloudinary に依存。外部サービス障害の影響を受ける可能性がある |
| 対応デバイス | Desktop・Tablet のみ。スマートフォン専用UIは対象外 |

## 9. 用語定義 / Glossary

| 用語 | 定義 |
|------|------|
| Admin | `role: "admin"` を持つ管理者ユーザー |
| Member | `role: "member"` を持つ一般従業員ユーザー |
| Channel | チャットの部屋。パブリック・プライベート・DM の3種類がある |
| Scope | コンテンツの公開範囲: company / group / personal / admin |
| Knowledge Base | 社内ドキュメント・SOP・オンボーディング資料などを管理するナレッジストア |
| Session Cookie | HTTP-only Cookie に格納された認証トークン。JavaScriptからアクセス不可 |
| DM | Direct Message。1対1のプライベートチャット |
